# JVM Interview Handbook

> This handbook contains frequently asked Java JVM interview questions with concise, interview-ready answers.

---

# JVM Basics

## 1. What is JVM?

The JVM (Java Virtual Machine) is an abstract machine that executes Java bytecode. It provides the runtime environment required to run Java applications and enables platform independence by converting bytecode into native machine code.

---

## 2. Why do we need JVM?

The JVM allows the same compiled Java program to run on different operating systems without recompilation. It also provides memory management, class loading, thread management, security and garbage collection.

---

## 3. What is Bytecode?

Bytecode is the intermediate instruction set generated by the Java compiler (`javac`). It is platform-independent and executed by the JVM.

---

## 4. Explain Java Execution Flow.

```
.java

↓

javac

↓

.class

↓

JVM

↓

Machine Code

↓

CPU
```

---

## 5. What happens after running `java Main`?

1. JVM starts.
2. Class Loader loads required classes.
3. Bytecode is verified.
4. Runtime memory is created.
5. Execution Engine executes bytecode.
6. Garbage Collector manages memory during execution.

---

# JDK, JRE and JVM

## 6. Difference between JDK, JRE and JVM.

| JDK | JRE | JVM |
|-----|-----|-----|
| Development Kit | Runtime Environment | Executes Bytecode |
| Contains Compiler | Contains JVM | Executes `.class` files |
| Used for Development | Used for Execution | Runtime Component |

---

## 7. Does JRE contain JDK?

No.

The JDK contains the JRE.

---

## 8. Does JVM compile Java code?

No.

The Java compiler (`javac`) compiles source code.

The JVM executes bytecode.

---

## 9. Can JVM execute `.java` files?

No.

The JVM executes compiled `.class` files.

---

## 10. Why is Java platform independent?

Java source code is compiled into platform-independent bytecode.

Different JVM implementations execute the same bytecode on different operating systems.

---

## 12. What are the major JVM components?

- Class Loader
- Runtime Data Areas
- Execution Engine
- Garbage Collector
- JNI
- Native Libraries

---

## 13. What is the role of the Class Loader?

The Class Loader loads compiled Java classes into memory before execution.

---

## 14. What is the Execution Engine?

The Execution Engine executes bytecode using the Interpreter and JIT Compiler.

---

## 15. Interpreter vs JIT Compiler?

| Interpreter | JIT |
|-------------|-----|
| Executes instruction by instruction | Compiles frequently executed code |
| Faster startup | Better runtime performance |
| No optimization | Optimized native code |

---

## 16. What is JNI?

JNI (Java Native Interface) enables Java code to communicate with native libraries written in languages such as C and C++.

---

## 17. Why are Native Libraries required?

Native Libraries allow Java applications to interact with operating system services and hardware-specific functionality.

---

# Runtime Memory

## 18. What are JVM Runtime Memory Areas?

- Heap
- Java Stack
- Method Area (Metaspace)
- Program Counter Register
- Native Method Stack

---

## 19. What is Heap Memory?

Heap stores objects and arrays. It is shared across all threads and managed by the Garbage Collector.

---

## 20. What is Java Stack?

The Java Stack stores method calls, local variables and reference variables. Every thread has its own Stack.

---

## 21. What is Metaspace?

Metaspace stores class metadata, runtime constant pool and static members. It replaced PermGen starting with Java 8.

---

## 22. What is the Program Counter Register?

It stores the address of the next JVM instruction to execute for each thread.

---

## 23. What is the Native Method Stack?

It supports execution of native methods written in languages such as C and C++.

---

## 24. Heap vs Stack?

| Heap | Stack |
|------|-------|
| Stores Objects | Stores Local Variables |
| Shared | Thread-specific |
| Managed by GC | Automatically cleaned |
| Larger | Smaller |

---

## 25. Where are objects stored?

Objects are allocated in the Heap.

---

## 26. Where are local variables stored?

Inside Stack Frames in the Java Stack.

---

## 27. Where are reference variables stored?

Reference variables are stored in the Stack, while the objects they point to reside in the Heap.

---

## 28. Where are static variables stored?

Static members are associated with the Method Area (Metaspace). If they reference objects, those objects are still stored in the Heap.

---

## 29. What is a Stack Frame?

A Stack Frame is created for every method invocation and contains local variables, parameters, operand stack and return information.

---

## 30. Does every thread have its own Heap?

No.

The Heap is shared across all threads.

Every thread has its own Stack.
