# What is JVM?

**JVM (Java Virtual Machine)** is an abstract machine that executes Java bytecode by converting it into platform-specific machine code.

It provides the runtime environment required to execute Java applications.

The JVM is one of the core components of the Java Platform.

---

# Why JVM Exists

Before Java,

software had to be compiled separately for each operating system.

For example,

```
Windows Program

↓

Runs only on Windows
```

A Linux machine cannot execute a Windows executable.

Java solved this problem by introducing the JVM.

```
Java Source Code

↓

Bytecode (.class)

↓

Platform Specific JVM

↓

Machine Code
```

This enables

> **Write Once, Run Anywhere (WORA)**

---

# Java Execution Flow

Every Java program follows the same execution flow.

```
Main.java

↓

javac Main.java

↓

Main.class

↓

java Main

↓

JVM Starts

↓

Class Loader

↓

Bytecode Verification

↓

Runtime Memory Allocation

↓

Execution Engine

↓

Machine Code

↓

CPU Executes Instructions
```

---

# Bytecode

Bytecode is the intermediate instruction set generated by the Java compiler.

```
.java

↓

javac

↓

.class
```

Important:

- Bytecode is **not machine code**.
- Bytecode is platform-independent.
- Bytecode can only be executed by a compatible JVM.

---

# Platform Independence

Java achieves platform independence because the **same bytecode** can be executed by different JVM implementations.

```
Bytecode

↓

Windows JVM

↓

Windows Machine Code

--------------------

Bytecode

↓

Linux JVM

↓

Linux Machine Code

--------------------

Bytecode

↓

macOS JVM

↓

macOS Machine Code
```

The JVM is platform-specific.

The bytecode is platform-independent.

---

# Responsibilities of JVM

The JVM is responsible for:

- Loading classes
- Verifying bytecode
- Allocating runtime memory
- Executing bytecode
- Managing threads
- Performing garbage collection
- Providing security checks
- Interacting with native libraries

---

# Components of JVM

The JVM consists of the following major components:

- Class Loader
- Runtime Data Areas
- Execution Engine
- Garbage Collector
- Java Native Interface (JNI)
- Native Libraries

# Common Misconceptions

❌ JVM compiles Java code.

Correct:

`javac` compiles Java code.

The JVM executes bytecode.

---

❌ Bytecode is machine code.

Correct:

Bytecode is an intermediate instruction set.

---

❌ JVM is platform-independent.

Correct:

The JVM implementation is platform-specific.

Java applications are platform-independent because they run on different JVM implementations.

---

# Key Takeaways

- JVM executes Java bytecode.
- Java source code is compiled into bytecode using `javac`.
- Bytecode is platform-independent.
- JVM converts bytecode into machine code.
- JVM provides memory management, class loading, and garbage collection.
- JVM enables Write Once, Run Anywhere (WORA).
